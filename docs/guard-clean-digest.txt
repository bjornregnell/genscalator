guard-clean reflexes (gs warm) — re-hydrate these at cold start so the FIRST bash calls do
not regress to base-model brittle bash. An active skill is LAZY: dormant until its trigger
fires, so at turn zero these reflexes are NOT salient unless you load them. Load them.

SEARCH / FILES   (never raw find / grep / ls | head / 2>/dev/null / command -v / which / type)
  tt files <DIR> <ext> [regex]              find files (dir first)
  tt text grepr <ABS-DIR> <ext> <regex>     recursive grep (dir first, metachar-free pattern)
  tt text match <file> <regex>              grep a single file
  tt which <name> [<name>...]               what IS a command: PATH hits, symlink chain, script-or-binary

SHELL HYGIENE
  ONE bare allowlist-matchable command per call  — no  cd && … , no  ;-chains , no compounds
  run_in_background                              — never  | head / | tail / | wc , never  > file
  keep shell metachars  ( | > < ` && ; )  OUT of quoted search patterns
  Write tool for files                           — never a  > redirect

GIT
  tt git commit --repo <dir> --message-file <path> --add <p> [--add …] --push
  write the message file FIRST (sequential), into the repo's gitignored tmp/ — NEVER the
  session scratchpad or /tmp (reboot-volatile, off-tree) ; no shell-glob metachars in
  commit PROSE ; no Claude-credit trailers .    Never  cd repo && git …
  tt gitinfo <repo> [--remote <name>]       branch, clean/dirty, ahead/behind, recent — for
    STATE/SYNC never raw  git status / git rev-list / git log --oneline  (reflex slips here).
  (commit-log SEARCH by grep/author/co-author trailer has no typed shape yet — SM217 gap;
   keep it a bare  git log --grep …  , NEVER piped to | head .)

⚠ THE TRIPWIRE  — the one line to internalise, because it fires at the ACTION, not at an abstraction:
  REACHING FOR python3 / jq / perl / node IS ITSELF THE SIGNAL that a typed verb is missing.
  Not "notice that a shape does not exist" — you will not notice; the 2026-07-24 specimen had that
  exact rule loaded and obeyed 4x in the same session, then broke it 30 min later. Notice the REACH.
  When it happens:  is there a tt verb?  ->  does the need RECUR (then build one, named after the
  noun)?  ->  else a one-off scratch or interpreter call is FINE — just SAY it was a one-off.
  Over-compliance is its own failure: hand-rolling a Scala scratch (5-20s compile) for a genuine
  one-liner is the WRONG trade. `tt guardcheck cmd "<cmd>"` now flags these as [NOTE].

DATA / JSON      (never  python3 -m json.tool , never  jq , never a hand-rolled parser)
  tt json check <file>                      parse-or-fail            (exit 0 = well-formed)
  tt json get <file> <path>                 one scalar, unquoted     (permissions.allow.3)
  tt json keys <file> [path]                an object's keys, or an array's length
  tt json pretty <file> [path]              indented, for READING — it sorts keys, so never
                                            write its output back over a human's file
  (SM228 specimen: the missing verb is exactly when the python3 reflex fires. The guard does
   NOT block that shape — no cd, no pipe, no redirect — so nothing catches it but you.)

DIRECTORIES      (a bare  cd  is guard-blocked, and rightly so)
  tt sbt --dir <abs> [sbt-args…]            run sbt somewhere else, no shell cd
  tt git --repo <dir> …                     the same move for git
  (other programs have no dir-scoped shape yet — flag the gap, do not reach for  cd )

URLS
  tt web get <url>                          fetch a URL — never raw curl / wget
    failures come back CLASSIFIED: [dns] [refused] [timeout] [tls] [unreachable] [reset]
  (remote-host checks over ssh have no typed shape yet — flag the gap, keep them minimal)
