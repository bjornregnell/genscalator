# Issue 011: `tt links check` — an ignore mechanism for by-design targets, then wire it into CI as a gate

> status: open · labels: toolbox, links, ci · summary: the repo is down to 6 dangling of 347 local
> links and ALL SIX are by design (generated files that exist only after a build step) — so the
> check can never reach 0, and it still runs in NO workflow, so nothing gates regressions.

## Description

Measured 2026-07-28. The remaining six: `docs/manual-src/*.md` citing `.html` siblings that exist
only after `tt ssg` generates them (5), and the serverless-spa-seed template's `index.html` citing
the `main.js` that its build step produces (1). Editing these links would turn them into lies; the
right move is recording each as a known, explained exception. And per the roadmap's gate-first
principle: `tt links check` carries an exit code built for gating, but `native-release.yml` is
still the only workflow — a checker nobody runs finds regressions nobody reads.

## Acceptance sketch

* An ignore mechanism (a checked-in exceptions file, or an inline rule) where every entry states
  WHY it is exempt — "generated by tt ssg", "generated by the seed's build" — so an exemption is
  documentation, not silence.
* With the six recorded, `tt links check` exits 0 on the repo, and CI runs it so a new dangling
  link fails loudly.
* The `--include-prose` widening stays OFF the CI exit code, keeping the gate's precision.
